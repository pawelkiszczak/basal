- **State cache on disk (opt-in):** `--state-cache-dir DIR` writes every state the state cache stores to DIR as a
  `.safetensors` file, one subdirectory per model signature (`--state-cache-gb` or `--prefix-cache on`; CUDA graph
  engine and `--mode mlx`, not Qwen3.5). The cache reads a state back from DIR when it misses in memory, exactly or
  as the longest prefix, so states survive restarts and other server processes can use them. `--state-cache-disk-gb`
  bounds the directory (default `auto`: half of the free disk space plus the files already there).
  `--state-cache-import any-engine` also reads the files the other engine wrote for the same bf16 checkpoint; the
  answers over those states are close to, not equal to, the uncached answers. On an
  Apple M4 Max (basal-2.0-mini, `--mode mlx`, 300 requests), a restart answered 300 / 300 readouts bit for bit as the
  uncached server, at the speed of memory hits (124 vs 141 ms p50; 330 ms without the cache).
  [HARDWARE.md](HARDWARE.md#state-cache-disk-tier). Contributed by Paweł Kiszczak (@pawelkiszczak),
  [#79](https://github.com/rkinas/basal/pull/79).
- **State cache management while the server runs:** `GET /v1/state-cache` shows both tiers, their budgets and
  counters; `POST /v1/state-cache/clear`, `/budget` and `/counters/reset` (admin key with `--api-keys`) clear the
  memory tier, this model's files or every model's, change a tier's budget until the server stops, and zero the
  counters; the `/ui` page has the same controls. A request with `"state_cache": "no-store"` reads cached states but
  stores none. `--state-cache-gb 25%` sizes the cache as a share of the host's RAM; `--state-cache-prune-days D`
  removes other models' cache directories unused for D days at start-up. [API.md](API.md#state-cache-management).
  Contributed by Paweł Kiszczak (@pawelkiszczak), [#79](https://github.com/rkinas/basal/pull/79).
